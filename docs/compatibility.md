# eliVibe 1.1.0 compatibility

eliVibe ships one teaching skill for Codex, Claude Code, and Oh My Pi (OMP). Codex and Claude Code use declarative plugins or a standalone skill. Only OMP has an executable adapter. See [installation](installation.md) for version-specific routes and the [maintained status ledger](https://github.com/taibenvenuti/elivibe/blob/main/docs/status.md) for exact tested revisions, public availability, and separate acquisition evidence.

For all three, the explanation supplements the handoff instead of replacing it. A bare request with no handoff in view needs the source; a self-contained concept question can get general background without a report. The OMP adapter handles missing source locally when the request needs a report. On Codex and Claude Code the distinction is skill guidance in an ordinary model turn, not a local check. Skill-only routes request no tools for explanation but do not impose the OMP adapter's explicit-turn tool veto. Unrelated work needs no new activation; previously invoked guidance may still be in conversation history. There is no second eliVibe inference client: explicit explanations and follow-ups can consume ordinary host requests and incur host costs; OMP automatic guidance adds no separate explanation request.

## Discovery and package contract

- **OMP:** Native `package.json` registers the extension; the package also ships `skills/elivibe/SKILL.md`. Standalone project discovery uses `.agents/skills/elivibe/SKILL.md`. Host skill commands must be enabled for `/skill:elivibe`. See the [adapter contract](integration.md) and [OMP skill discovery](https://github.com/can1357/oh-my-pi/blob/v19.2.1/docs/skills.md).
- **Codex:** [Skills](https://developers.openai.com/codex/skills/) documents project and home `.agents/skills/` and the `agents/openai.yaml` policy `allow_implicit_invocation: false`. Keep that file with `SKILL.md`. The [plugin contract](https://developers.openai.com/codex/plugins/) and [pinned marketplace loader](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/core-plugins/src/marketplace.rs) support this repo's `.agents/plugins/marketplace.json` → `./skills` → `.codex-plugin/plugin.json` layout. A registered directory remains a local marketplace even if the directory is a Git checkout; native Git marketplace upgrade is not the local reinstall tested here.
- **Claude Code:** [Skills](https://code.claude.com/docs/en/skills) documents project `.claude/skills/`, user `~/.claude/skills/`, and `disable-model-invocation: true`. The [plugin](https://code.claude.com/docs/en/plugins/create) and [marketplace contracts](https://code.claude.com/docs/en/plugin-marketplaces) describe this repo's `.claude-plugin/marketplace.json` → `./skills` → `.claude-plugin/plugin.json` layout and [scope controls](https://code.claude.com/docs/en/plugins/cli-reference). `--plugin-dir` exposed one qualified command with a host alias, not a second installed command. The tested `owner/repo#ref` shorthand requires a branch or tag; a raw commit SHA did not work there.

Each marketplace points to the narrow, licensed `skills/` package root. Both native plugin manifests lead to the same `elivibe/SKILL.md`. We rejected one portable root `plugin.json`: [Codex 0.162.1 recognizes a schema-qualified Agent Plugins manifest](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/utils/plugins/src/plugin_namespace.rs), but that does not establish Claude Code's documented package and validation contract. The two small native manifests preserve each host's discovery and listing metadata without duplicating the skill or making the entire OMP checkout the plugin payload.

The Codex test used [App Server](https://developers.openai.com/codex/app-server/) turn execution (`turn/start` → `run_turn`) and the real TUI picker, not `debug prompt-input`, which bypasses turn-time injection ([#40600](https://github.com/openai/codex/issues/40600)). On 0.162.1 the picker inserted the correct lowercase qualified mention for the package and the turn contained the skill body ([#43727](https://github.com/openai/codex/issues/43727)). Literal `$elivibe:elivibe` and structured selection worked packaged; unqualified `$elivibe` did not. Fresh ordinary input did not expose the skill description or body. These are results for this skill and pin, not a claim that all reported upstream cases are fixed.

**CLI is the tested surface.** OpenAI's [skill guide](https://learn.chatgpt.com/docs/build-skills) documents standalone skills in Codex CLI, the ChatGPT desktop app and the IDE extension. Its [plugin guide](https://learn.chatgpt.com/docs/plugins) distinguishes the CLI browser from supported ChatGPT surfaces and explicitly says the **IDE extension does not support plugins**. The CLI marketplace command is not an IDE install recipe. Anthropic documents a [separate desktop customization UI](https://code.claude.com/docs/en/desktop); this trial used the Claude Code CLI, not that UI. These vendor capabilities do not verify eliVibe on desktop, IDE, web or mobile.

## CLI marketplaces versus vendor directories

Adding this project's marketplace source to a CLI is not being listed by the vendor. Vendor submission and approval are outside the 1.1.0 release; the [maintained status ledger](https://github.com/taibenvenuti/elivibe/blob/main/docs/status.md) tracks distribution evidence separately.

| Directory | Documented path, separate from CLI install |
|---|---|
| OpenAI | [Submit a plugin](https://developers.openai.com/plugins/deploy/submission) via the [Plugins dashboard](https://platform.openai.com/plugins). Select the owning organization/project (owner or **Apps Management Write**), choose the verified individual or business developer identity displayed in the listing, and upload a supported plugin ZIP as **Skills only**. Resolve required metadata/skill checks, attest and submit for review; separately publish after approval. The standalone skill ZIP is not a directory submission package. |
| Anthropic | [Submit a plugin](https://claude.com/docs/plugins/submit#submit-a-plugin) in the [directory developer portal](https://claude.ai/directory/manage) from an [eligible paid account](https://claude.com/docs/directory/publish#confirm-you-can-submit-to-the-directory) (Team/Enterprise Owner or Enterprise **Directory** permission, where applicable). Provide the GitHub source, run strict local validation, and meet portal checks; published listings can [sync into Claude Code as `<name>@synced`](https://code.claude.com/docs/en/plugins/loading#synced-plugins). The [official Claude Code marketplace](https://github.com/anthropics/claude-plugins-official) does not take pull-request submissions; [its listing path](https://code.claude.com/docs/en/plugins/publish#submit-to-anthropics-directory) is separate from the directory portal. |

- **Future only:** Pi documents [standalone skills](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md), [packages](https://docs.pi.dev/latest/packages), and a [package gallery](https://pi.dev/packages). These results do not establish other host versions, platforms or providers, directory acceptance, security certification, or explanation effectiveness.
