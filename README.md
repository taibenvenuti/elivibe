# eliVibe

**eliVibe is a skill for coding agents that helps you understand why the work matters.** It adds a distinct explanation to the technical handoff without replacing the report, repeating all of its evidence, or claiming to verify the work.

**Report:** “The restored archive's checksum matched. We haven't opened it in the application.”

**eliVibe supplement:** “A checksum is a fingerprint of the bytes. Matching one is evidence that the copy matches the reference, not that the application can use those bytes. A restore test checks the missing link: can the application actually open and use the restored data?”

This illustration was written for the docs, not generated by a model or observed in a real restore. See a [longer handoff and deeper questions](https://github.com/taibenvenuti/elivibe/blob/v1.1.0/docs/qa-examples.md#9-a-full-handoff-with-follow-up-questions).

## Try it

Use a coding agent you already have working. eliVibe uses that agent's ordinary conversation and model, with no separate account, key, or build. Install **one** copy per host.

These quickstarts install eliVibe 1.1.0 from [GitHub](https://github.com/taibenvenuti/elivibe/releases/tag/v1.1.0) or, for Oh My Pi, [npm](https://www.npmjs.com/package/elivibe/v/1.1.0).

### Codex

```sh
codex plugin marketplace add taibenvenuti/elivibe@v1.1.0 &&
  codex plugin add elivibe@elivibe
```

In a new Codex session, finish a task. Type `$`, choose **elivibe (elivibe)**, and send `$elivibe:elivibe` on its own to explain the handoff you just got.

### Claude Code

```sh
claude plugin marketplace add 'taibenvenuti/elivibe#v1.1.0' --scope local &&
  claude plugin install elivibe@elivibe-marketplace --scope local
```

Run this from the project where you want eliVibe; `local` keeps the registration out of shared project settings. In a new Claude Code session, finish a task and enter `/elivibe:elivibe` on its own.

### Oh My Pi (OMP)

```sh
omp plugin install elivibe@1.1.0
```

In a new OMP session, finish a task and enter `/elivibe` on its own. Prefer GitHub or an offline archive? [Choose one installation source](https://github.com/taibenvenuti/elivibe/blob/main/docs/installation.md#omp-installation-sources). If you already have a copy, [check its source](https://github.com/taibenvenuti/elivibe/blob/main/docs/installation.md#check-the-installation) before switching.

For any host, add a focused follow-up in the same conversation. For the example above, ask “What would opening the restored archive actually prove?” Adapt the question to your report's evidence, then continue coding without invoking eliVibe again. No report handy? [Try a copyable fictional handoff](https://github.com/taibenvenuti/elivibe/blob/main/docs/installation.md#try-your-first-explanation).

## OMP commands

| In OMP | What it does |
|---|---|
| `/elivibe` | Ask for a distinct explanation of the latest applicable handoff. Default mode is **Manual**: nothing is added automatically. |
| `/elivibe Why isn't a passing checksum enough?` | Ask a specific question. `/elivibe explain` and `/elivibe explain <question>` also work; use the latter if the question starts with a command word. |
| `/elivibe more` | Go deeper on the latest applicable eliVibe explanation. Its original handoff must still be available. If it isn't, supply the relevant non-sensitive facts in a self-contained `/elivibe explain <question>` and follow up in the same conversation. |
| `/elivibe light` | For later tasks on this session branch, teach only when a meaningful gap warrants it. |
| `/elivibe full` | For later tasks on this session branch, explain meaningful technical handoffs after the ordinary report. |
| `/elivibe manual` or `/elivibe off` | Disable automatic explanations. Explicit commands still work in both modes (and in Light and Full). `/elivibe mode <mode>` is an equivalent setter. |
| `/elivibe depth auto`, `brief`, or `detailed` | Fit the explanation to the task, focus on the key distinction, or show connected concepts and consequences. `adaptive` is an alias for `auto`, the default. |
| `/elivibe status` or `/elivibe help` | Inspect settings or command usage without asking the model. |
| `/elivibe settings` | Open the terminal mode/depth picker. Cancel to leave settings unchanged. If the picker is unavailable, use the text commands shown instead. |

Light and Full add instructions to ordinary turns, not a separate judgment or model request. Your selected depth applies in both modes. An explicit explanation or `more` is another ordinary turn using the active OMP model and conversation; it can include more context than the report alone. Say “skip eliVibe for this reply” or ask for an exact output format to keep that reply free of a supplement. The report is the source account; eliVibe does not approve actions or independently verify conclusions.

See the [tested CLI combinations](https://github.com/taibenvenuti/elivibe/blob/v1.1.0/docs/compatibility.md) and [what reaches the model](https://github.com/taibenvenuti/elivibe/blob/v1.1.0/docs/privacy.md). A successful installation is not a measurement of teaching effectiveness.
